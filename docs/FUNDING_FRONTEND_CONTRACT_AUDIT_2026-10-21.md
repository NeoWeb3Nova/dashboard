# 资金费策略前后端一致性审计与修复

2026-10-21，北京时间。范围覆盖资金费策略配置页、运行账本/MQTT/API 输出、持仓和平仓视图、动态观察池及控制请求。基差系统只做隔离核对，保留其未提交改动；未修改官方连接器、执行器、时钟、API 编排及交易引擎代码。

## 生效与边界

开发、测试和提交均在 `audit/funding-contract-20261021` 的 Dashboard worktree 中完成，再快进合入主分支，通过现有前端热加载生效。API/Core 本轮无代码变更，前端更新没有重启交易机器人。后续在线验收发现实际 HTTP 418，已按下节记录主动暂停空仓机器人和原验收窗口，不能继续表述为完整连续健康观察。

后台现有控制通道没有逐命令完成回执，本轮不声称实现了执行确认；界面只显示提交状态，并通过后续账本查看效果。单槽待处理请求不会被覆盖，不等于提供无限队列或服务端事务。配置同名保护防止该页面误覆盖；不代替其他 API 客户端的并发管理。

整轮扫描总耗时仍未由引擎上报，公共数据拉取耗时继续单独显示。本轮没有用重启当前模拟盘来补这个指标，也没有把空仓、回归通过或拒绝样本当作盈利证据。


## 在线复核追加：HTTP 418 与验收中断

最终核对发现 Binance 返回真实 HTTP 418/-1003，响应含 `banned until` 时间戳，且原生连接器反复重连；日志指示截止北京时间 **2026-10-21 19:37:59.978**。不把这个时间当作保证恢复，不更换 IP 或绕过交易所限制；根因可能涉及共享出口与重试负载，当前证据不足以归责给某个单一请求源。

后台拒绝过期元数据开仓，但扫描 `phase=ready` 仍可能意味着本轮全部因过期数据被筛掉。前端已增加盘口/规则不齐、费率元数据不齐、刷新失败与过期筛选提示，不能把进程运行或扫描完成显示成行情健康。

新增 `funding_http.py` 对前端独立公共雷达的 418/429 响应实施退避，使用响应的封禁时间及 Retry-After；没有明确时间时本地暂按 418 等待 15 分钟、429 等待 60 秒，属于本地策略而非官方保证。状态持久化于现有 `bots/data/funding_public_backoff.json`，不保存响应里的出口 IP。刷新/模块缓存重建不会绕过已记录的退避。

核实当前资金费模拟实例为 **0 持仓、0 平仓** 后，于北京时间 **15:34:29** 主动停止该容器，保留 API、Postgres、Broker、前端和基差未提交改动。未修改官方连接器以热补丁方式绕过限流。原采样进程经精确命令行核对后停止，保存 `acceptance-before-interruption.json`、原 `samples.jsonl` 和 `interruption.json`，`acceptance.json` 明确标记 `interrupted/needs_investigation`。最终 101 份样本中 91 份健康，比例约 90.10%；盈亏为零不代表通过。

没有配置自动重启或额外服务。封禁时间届满后仍需确认限流解除、请求负载及行情恢复，再启动模拟盘并另开验收窗口；不能拼接旧窗口或声称已自动恢复。
